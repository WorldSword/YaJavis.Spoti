# Яндекс Умный дом — модуль Rust

Реализация находится в `jarvis/modules/yandexhome/`, без зависимости от ядра и Go.
Подключается отдельной Cargo feature `yandexhome`:

```sh
JARVIS_FEATURES=homeassistant,yandexhome scripts/rs-build.sh 0.9.71-rs
# Или только Яндекс:
cd jarvis
cargo build --release --target aarch64-unknown-linux-musl --features yandexhome
```

Модуль из выбранной сборки можно установить через каталог плагинов. Экран
«Яндекс Умный дом» привязан к его провайдеру и не требует общего Go-плагина `home`.
При включении отдельного модуля прежний объединённый провайдер его не подменяет.

Токен вводится в существующем экране подключения. Перед сохранением модуль
проверяет доступ к каталогу; неудачная проверка сохраняет прежний токен.
Пустой токен отключает подключение. Требуются права `iot:view` и `iot:control`
из [официального протокола Яндекса](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-protocol).

Перенесены:

- каталог устройств, комнат, групп, активных сценариев и голосовых фраз;
- контекст возможностей для модели и общий инструмент `smart_home`;
- быстрые команды включения/выключения, цвета и температуры белого;
- выбор света в комнате колонки или в явно названной комнате;
- RGB/HSV, яркость, диапазоны, режимы и переключатели по возможностям устройства;
- запуск активных сценариев и управление включением групп;
- кэш каталога по аккаунту с обновлением после действий;
- сетевой маршрут из ядра: напрямую или через выбранный VPN.

Подтверждение устройства проверяется по его ID, типу умения и instance.
Отсутствующий результат, `ERROR`, неполное подтверждение группы и неизвестные
устройства не считаются полным успехом. Формат сверяется с документацией
[действий устройств](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-capabilities)
и [действий группы](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/platform-group-capabilities).

Модуль принимает маршрут отдельным аргументом от хоста, игнорирует прокси из
переменных окружения и при ошибке выбранного VPN возвращает ошибку подключения.
Запросы изменения состояния не повторяются автоматически. В ядре также закрыто
окно прямого подключения до запуска VPN или при смене его настроек.

Проверка без реального дома:

```sh
cd jarvis
cargo test --workspace --features homeassistant,yandexhome
```

Тесты поднимают локальный сервер с ответами протокола Яндекса. Проверка на живой
колонке и реальном аккаунте отдельно; автоматическая сборка набора модулей
через панель ещё не перенесена.
