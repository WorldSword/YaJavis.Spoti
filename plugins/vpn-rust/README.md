# VPN на Rust: VLESS, REALITY и Vision

Отдельная необязательная библиотека `jarvis-vpn`, Cargo feature `vpn`.
Работает внутри Rust-ядра через общий хост модулей. Не запускает Go/Xray,
не устанавливает системный прокси и не меняет маршруты колонки.

Это Rust-реализация туннеля. Полная совместимость со всеми настройками прежнего
Xray-модуля ещё не достигнута: ограничения перечислены ниже.

Поддерживается:

- VLESS TCP (`type=tcp` или `raw`) и WebSocket (`type=ws`);
- `security=none`, `tls` и `reality`, `encryption=none`;
- REALITY: X25519, short ID, аутентификация сертификата HMAC-SHA512 и подписи Ed25519;
- REALITY `fp=chrome`/`chrome133` и алиасы (`edge`, `safari`, `ios`, `android`, `random`, `randomized`, `qq`, `360`): Chrome 133 ClientHello, GREASE, перестановка расширений, X25519+ML-KEM-768 и Brotli для сертификатов; профиль закреплён, не обновляется сам;
- REALITY `fp=firefox`/`firefox120`: профиль Firefox ClientHello;
- Vision (`flow=xtls-rprx-vision` и TCP-алиас `xtls-rprx-vision-udp443`) поверх TCP с TLS 1.3/REALITY;
- потоковое снятие Vision padding, независимый переход чтения/записи на raw TCP по границам TLS-записей;
- TLS с проверкой сертификата и имени сервера, `sni`/`peer`, явный `allowInsecure=1`;
- WebSocket `host` и `path`, бинарные сообщения, ограниченные буферы;
- локальный SOCKS5 CONNECT и UDP ASSOCIATE на `127.0.0.1`, обязательные случайные имя и пароль;
- UDP через VLESS command 2 с границами пакетов, максимум 8190 байт, без прямой отправки наружу;
- UDP-сессия привязана к TCP-авторизации, IP и порту клиента; фрагменты SOCKS не принимаются;
- до 8 UDP-направлений на ассоциацию, 32 на весь модуль, ограниченные очереди и таймер простоя;
- IPv4, IPv6 и передача домена назначения серверу VLESS без локального DNS этого домена;
- максимум 64 соединения, включая незавершённые рукопожатия, по 15 секунд на SOCKS и подключение;
- повторный запрос с той же ссылкой переиспользует слушатель;
- изменение ссылки, её очистка и выключение плагина закрывают существующие соединения.

Chrome/Firefox ClientHello для обычного `security=tls` (используется профиль `rustls`, при этом распространённые браузерные `fp` в ссылке принимаются), UDP с Vision (нужен XUDP), ML-DSA REALITY, gRPC, XHTTP,
VLESS Encryption и WebSocket early data пока отсутствуют. ALPN для TCP допускает `h2`, `http/1.1` и `h2,http/1.1`; WebSocket требует `http/1.1`.
Неподдержанный `fp` или неподходящие настройки сразу возвращают ошибку на проверке ссылки; модуль не пробует прямой маршрут.
Chrome и Firefox REALITY доступны с `security=reality`; подписка ChatGPT использует его UDP-туннель для ICE/DTLS/RTP.
REALITY требует явного SNI и `pbk`; `allowInsecure` не отключает его аутентификацию.
Spider/fallback к сайту прикрытия не выполняется. Неверный ключ или short ID закрывает соединение.

REALITY использует отдельную vendored-зависимость rustls с закреплённым исходным commit, без глобальной
замены TLS в ядре и других модулях. Источники и лицензии: `jarvis/modules/vpn/THIRD-PARTY.md`.

## Выбор модуля

```sh
cd jarvis
cargo build --release --target aarch64-unknown-linux-musl --features vpn
cargo run -p jarvis --features vpn -- modules
cargo test -p jarvis-vpn
```

Наличие feature добавляет код и манифест в сборку. Установка модуля из каталога
включает его через `kind=module`, `id=main=provides[0]=vpn`.
Дескриптор находится здесь, чтобы не изменять прежний нативный пакет `plugins/vpn`.
Архив содержит только `plugin.json`; без feature ядро не сможет его запустить.
Сборка без feature `vpn` не включает `jarvis-vpn`.

Метод `vpn` принимает `{ "link": "vless://…" }` и возвращает
`{ "socks", "user", "pass", "udp", "info" }`; пустая ссылка возвращает `{}`.
`udp` явно сообщает клиенту о возможности UDP; у Vision он `false`.
`info` не содержит UUID, исходную ссылку или пароль.
Метод `vpn.validate` проверяет ссылку без открытия сокетов и изменения туннеля.

Rust API `PUT /api/vless` использует проверку выбранного провайдера до сохранения.
Неподдержанная ссылка оставляет текущие настройки и туннель. Очистка работает
и без установленного провайдера. Проверка этим API прежнего native-провайдера,
у которого нет `vpn.validate`, пока не поддерживается.
Применение нового адреса не проверяет доступность сервера: соединение создаётся
при первом SOCKS CONNECT. Отказ сервера не приводит к прямому подключению.

Проверено локальными сетевыми тестами с VLESS-серверами TCP, TLS, WS и WSS,
включая задержанный ответ VLESS, фрагментацию, недоверенный сертификат,
авторизацию SOCKS, лимит соединений и остановку через хост плагинов.
REALITY и Vision дополнительно проверяются против независимого Xray 26.3.27:
`JARVIS_XRAY=/path/to/xray cargo test -p jarvis-vpn` включает эти тесты.
Xray используется только как локальный тестовый сервер и не входит в прошивку.
Гибридный обмен можно дополнительно проверить с внешним TLS-сайтом прикрытия, который принимает
только X25519MLKEM768: соберите `jarvis/modules/vpn/test-peer/tls-cover.go`, задайте путь `JARVIS_TLS_COVER`.
Реальная VLESS REALITY-ссылка с `fp=chrome` проверена HTTPS-запросом и облачным
звонком ChatGPT с входящей речью, распознаванием и ответом Opus через Rust VPN.
