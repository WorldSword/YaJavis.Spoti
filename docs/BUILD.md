# Сборка из исходников


Нужны Go версии из `jarvisd/go.mod`, Zig с поддержкой указанных Linux-целей и POSIX shell. Python и видеокарта для обычной сборки не требуются. Обученные классификаторы активации входят в `models/`; исходные аудиозаписи не распространяются.

```sh
git clone https://github.com/newfpv/YaJavis.git
cd YaJavis
(cd jarvisd && go test ./...)
VERSION=0.9.43 RELEASE=1 sh build.sh
```

Если Go или Zig отсутствуют в `PATH`, укажите `GO=/путь/к/go ZIG=/путь/к/zig`. Результат — `build/release/`, включая установщики, файлы колонки и `SHA256SUMS`. Сборка никогда не читает локальные `.env` или настройки автоматически.

Без переменных `GDRIVE_CLIENT` и `GDRIVE_SECRET` сборка работает без общего Google OAuth-клиента. Для официальных релизов эти два значения берутся из GitHub Actions Secrets; сгенерированный файл с зашифрованным приложением не входит в Git и удаляется после сборки. Прочие ключи в сборку не передаются.

Перед выпуском добавьте `docs/releases/ВЕРСИЯ.md` по шаблону `.github/RELEASE_TEMPLATE.md`: что нового, исправления и способ обновления. Без этого файла автоматическая публикация не запускается.

Тег вида `v0.9.43` запускает `.github/workflows/release.yml`: тесты, сборку и публикацию релиза с подготовленным описанием. Для локальных сетевых проверок используйте выборочные тесты с `JARVIS_NET=1`; обычный запуск тестов не требует входа в аккаунты.

## Структура

| Каталог | Назначение |
| --- | --- |
| `jarvisd/` | Программа колонки и веб-панель |
| `installer/` | Установщик с собственным ADB-клиентом |
| `station/` | Подключение микрофона и запуск сервиса |
| `models/` | Веса распознавания активации |
| `kws/` | Дополнительные инструменты обучения на своих записях |
| `scripts/` | Инструменты сборки (`pack-plugins.go` упаковывает официальные плагины) |
| `plugins/` | Официальные плагины и их список `index.json` ([как писать плагины](PLUGINS.md)) |
| `pluginsdk/` | Обёртка для нативных плагинов на Go |

## Веб-панель

Панель — обычные ES-модули без фреймворка и без шага сборки: файлы из `jarvisd/ui` встраиваются в программу как есть.
Для разработки запустите `jarvisd -ui jarvisd/ui …`: тогда панель отдаётся с диска, и правки видны после обновления страницы.

| Файл `jarvisd/ui/js/` | Что внутри |
| --- | --- |
| `main.js` | Точка входа: вход, состояние с колонки (`S`), опрос, сайдбар, маршруты |
| `core.js` | Общее: `$`, `api`, `toast`, `act`, иконки, пружины, ползунки, плашка переключателей, `dirty`/`setDirty` |
| `home.js`, `feed.js` | Главная и переписка на ней |
| `assistant.js`, `characters.js` | Ассистент (голос, модель, характер) и характеры |
| `connections.js` | Подключения и память Джарвиса |
| `speaker.js`, `leds.js` | Колонка и подсветка |
| `player.js`, `charts.js`, `logs.js` | Плеер, графики, логи |
| `security.js`, `training.js` | Безопасность и обновления, обучение слова |
| `plugins.js`, `wizard.js` | Плагины и мастер знакомства |

Правило модулей: изменяемое состояние меняет только модуль, который его объявил (`S` и `page` — `main.js`,
плеер — `player.js`); остальные читают его через импорт или вызывают функцию-сеттер. Модули не выполняют
код при загрузке, кроме навешивания обработчиков: всё запускает `main.js`.

Для удаления запустите установщик и выберите удаление. Он также используется для восстановления установки.
