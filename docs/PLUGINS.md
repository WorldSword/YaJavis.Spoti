# Плагины YaJarvis: как это устроено и как написать свой

Ядро Джарвиса становится лёгким. В нём остаётся то, без чего колонка не работает: микрофон, слово «Джарвис»,
динамик, подсветка, кнопки, связь с Алисой, панель, обновления и менеджер плагинов. Всё остальное ставится
плагинами. Встроенные функции (YouTube, ChatGPT, VPN, умный дом) переезжают в официальные плагины постепенно,
а обновление ставит их само ([как](#official)). Плагин может написать кто угодно и выложить на GitHub,
а Джарвис найдёт его сам.

<a id="user"></a>
## Как плагины выглядят для пользователя

Панель → **Плагины**. Наверху переключатель:

- **Официальные.** Плагины из этого репозитория (папка [`plugins/`](../plugins)) и список
  [`plugins/index.json`](../plugins/index.json). Их делает и проверяет автор YaJarvis.
- **Неофициальные.** Всё остальное: репозитории GitHub с темой `yajarvis-plugin` и архивы, поставленные из файла.

Внутри каждой стороны плагины разложены по **категориям** (кнопки «Все», «Умный дом», «Погода и справки»…).
Переключатель «Только установленные» оставляет только то, что уже стоит.

У установленного плагина в карточке: включить/выключить, «Настроить» (если у плагина есть настройки),
«Обновить до …» (если в каталоге версия новее), удалить. У неустановленного — «Установить».

Перед первой установкой неофициального плагина панель предупреждает: плагин написал не автор YaJarvis,
никто его не проверял, автор проекта за него не отвечает. Галочка «Больше не показывать» убирает предупреждение навсегда.

Кнопка **«Из файла»** ставит плагин из `.zip`, например скачанного из релиза. Такой плагин всегда считается неофициальным.

При первом входе в панель мастер знакомства предлагает поставить рекомендованные официальные плагины.

<a id="kinds"></a>
## Два вида плагинов

| | JS-плагин (`"kind": "js"`) | Нативный плагин (`"kind": "native"`) |
| :--- | :--- | :--- |
| Что это | `plugin.json` и скрипт на JavaScript | `plugin.json` и программа под процессор колонки |
| Вес | килобайты | от 2–3 МБ (Go), сколько получится |
| Сборка | не нужна | под `arm64` и `armv7` (32-битный ARM: Стрит, Мини 1/2) |
| Где работает | внутри Джарвиса, во встроенном движке goja | отдельным процессом рядом с Джарвисом |
| Доступ | только объект `jarvis`: сеть, хранилище, Алиса, голос | всё, что может программа на колонке (root) |
| Для чего | навыки, справки, интеграции с HTTP API, быстрые команды | тяжёлое: голосовые движки, декодирование звука, VPN, свои протоколы |

Если сомневаетесь, пишите JS-плагин: его проще сделать, он безопаснее для пользователя и работает на любой колонке.

<a id="quick"></a>
## Плагин за пять минут

Папка с двумя файлами:

```
coin/
├── plugin.json
└── main.js
```

`plugin.json`:

```json
{
  "id": "coin",
  "name": "Монетка",
  "version": "1.0.0",
  "description": "Подбросить монетку: «Джарвис, подбрось монетку».",
  "author": "ваш ник",
  "homepage": "https://github.com/вы/yajarvis-coin",
  "kind": "js",
  "main": "main.js",
  "api": 1,
  "category": "fun",
  "icon": "puzzle"
}
```

`main.js`:

```js
// Быстрая команда: фраза разбирается без нейросети, ответ Джарвис скажет голосом.
jarvis.command(["(подбрось|брось|кинь) монет(ку|у)", "орел или решка"],
  () => (Math.random() < 0.5 ? "Орёл." : "Решка."));

// Инструмент: нейросеть сама решит, когда его вызвать («кинь жребий, кто моет посуду»).
jarvis.tool({
  name: "coin_flip",
  description: "Честно подбросить монетку.",
  parameters: { type: "object", properties: {} },
}, () => (Math.random() < 0.5 ? "орёл" : "решка"));
```

Упакуйте содержимое папки в zip (`plugin.json` в корне архива или в одной папке верхнего уровня, как
делает GitHub) и поставьте: панель → Плагины → «Из файла». Скажите «Джарвис, подбрось монетку».

Готовые примеры: [`plugins/dice`](../plugins/dice) (самый простой),
[`plugins/weather`](../plugins/weather) (запросы в интернет, кеш, настройки, статус),
[`plugins/currency`](../plugins/currency) (выбор из списка в настройках).

<a id="manifest"></a>
## plugin.json: все поля

| Поле | Обязательно | Что это |
| :--- | :---: | :--- |
| `id` | да | Уникальное имя: латиница в нижнем регистре, цифры и дефис, 2–32 символа. По нему плагин хранится на колонке (`/data/opt/jarvisd/plugins/<id>`). Не меняйте его между версиями. |
| `name` | да | Название в панели. |
| `version` | да | Версия, например `1.2.0`. По ней панель предлагает обновление. |
| `description` | желательно | Одна-две фразы: что умеет и как попросить. |
| `author` | желательно | Ник или имя. |
| `homepage` | желательно | Ссылка на код (панель показывает её как «код»). |
| `kind` | да | `js` или `native`. |
| `main` | да | JS: файл скрипта, например `main.js`. Native: программа, `{arch}` заменяется на `arm64` или `armv7`, например `bin/myplugin-{arch}`. |
| `category` | да | Раздел каталога, одна из [категорий](#categories). Без неё плагин не установится. |
| `api` | желательно | Версия API, под которую написан плагин. Сейчас `1`. Если плагин требует больше, чем знает ядро, он не установится, а пользователь увидит «обновите Джарвиса». |
| `min_core` | нет | Минимальная версия Джарвиса, например `0.9.68`. |
| `icon` | нет | Иконка из набора панели: `puzzle`, `cloud`, `bolt`, `home`, `music`, `mic`, `radio`, `wifi`, `moon`, `shield`, `search`, `link`, `voice`, `speaker`. Неизвестная — `puzzle`. |
| `provides` | нет | Подсказка, что даёт плагин: `tools`, `commands`, `engine`, `music`, `vpn`. Пока только для информации. |
| `settings` | нет | Поля настроек, панель нарисует форму сама. См. [Настройки](#settings). |

<a id="categories"></a>
## Категории

Автор выбирает **ровно одну** категорию: в `plugin.json` (поле `category`) и темой репозитория на GitHub
(`yajarvis-<id>`). В панели разделы идут в этом порядке, «Другое» всегда последним.

| `category` | Название в панели | Что сюда |
| :--- | :--- | :--- |
| `assistant` | Ассистенты и голоса | голосовые движки, нейросети, голоса, характеры |
| `home` | Умный дом | свет, розетки, датчики, сценарии, пылесосы |
| `media` | Музыка и видео | музыка, радио, подкасты, видео, аудиокниги |
| `info` | Погода и справки | погода, курсы, новости, транспорт, справочники |
| `productivity` | Дела и заметки | списки, напоминания, календари, почта, заметки |
| `dev` | Кодинг и IT | серверы, GitHub, CI, мониторинг, сеть, домашняя лаборатория |
| `fun` | Игры и развлечения | игры, шутки, викторины, жребий, сказки |
| `system` | Колонка и система | подсветка, кнопки, слово активации, VPN, обслуживание колонки |
| `other` | Другое | всё, что не подошло выше |

Не нашли подходящую — ставьте `other` и напишите в [issues](https://github.com/newfpv/YaJavis/issues),
какой категории не хватает.

<a id="settings"></a>
## Настройки плагина

Каждое поле в `settings` становится строкой формы в панели (кнопка «Настроить»):

```json
"settings": [
  {"key": "token", "label": "Токен API", "type": "password", "hint": "Где взять: личный кабинет → API", "required": true},
  {"key": "city", "label": "Город", "type": "text", "hint": "Пусто — город из настроек ассистента"},
  {"key": "units", "label": "Единицы", "type": "select", "options": ["метрические", "имперские"], "default": "метрические"},
  {"key": "fast", "label": "Отвечать без нейросети", "type": "bool", "default": true},
  {"key": "limit", "label": "Сколько новостей", "type": "number", "default": 3},
  {"key": "note", "label": "Заметка", "type": "textarea"}
]
```

| `type` | Поле | Значение в `jarvis.settings` |
| :--- | :--- | :--- |
| `text` | строка | строка |
| `password` | скрытая строка | строка. В панель возвращаются только последние 4 символа, а пустое поле при сохранении значит «оставить как было» |
| `number` | число | число или `null` |
| `bool` | переключатель | `true` / `false` |
| `select` | список `options` | одна из строк `options` (другое значение ядро не сохранит) |
| `textarea` | многострочный текст | строка |

`default` подставляется, пока пользователь ничего не задал. Настройки хранятся на колонке в
`/data/opt/jarvisd/plugins.json` (права 0600) и обратно в браузер целиком не отдаются.

<a id="js"></a>
## JS-плагины: объект jarvis

Скрипт выполняется один раз при запуске плагина. В нём вы регистрируете команды, инструменты и фоновые задачи.
Всё синхронно: `jarvis.fetch` сразу возвращает ответ, `await` не нужен (async-функции тоже работают).
Один плагин выполняет один вызов за раз. Другим плагинам и самому Джарвису он не мешает.

| Что | Описание |
| :--- | :--- |
| `jarvis.command(шаблоны, fn)` | Быстрая команда без нейросети. См. [Быстрые команды](#commands). |
| `jarvis.tool(описание, fn)` | Инструмент для нейросети. См. [Инструменты](#tools). |
| `jarvis.fetch(url, opts)` | HTTP(S)-запрос. `opts`: `method`, `headers`, `body` (строка или объект → JSON), `timeout` (секунды, до 60, по умолчанию 15). Возвращает `{status, ok, text, headers, json()}`. Ответ — до 2 МБ. Через VPN, если в «Подключениях» отмечено «Плагины». |
| `jarvis.settings` | Текущие настройки плагина (объект). Меняются без перезапуска. |
| `jarvis.onSettings(fn)` | Вызов, когда пользователь сохранил настройки: `fn(settings)`. |
| `jarvis.store.get(k)` / `.set(k, v)` / `.all()` | Хранилище плагина (JSON, до 256 КБ, файл `data.json`). Переживает перезапуск и обновление плагина. `set(k, null)` удаляет. |
| `jarvis.say(text)` | Сказать голосом активного ассистента (до 600 символов). |
| `jarvis.alice(text, silent)` | Текстовый запрос штатной Алисе («включи свет в зале»). `silent: true` — без её голосового ответа. Возвращает `true`, если запрос ушёл. |
| `jarvis.every(секунды, fn)` | Фоновая задача, не чаще раза в 60 секунд. |
| `jarvis.status(text)` | Строка состояния под плагином в панели («город: Минск», «ключ не задан»). |
| `jarvis.info()` | `{city, timezone, room, language, model, assistant}`: город и часовой пояс активного ассистента, комната колонки, язык, модель колонки. |
| `jarvis.log(...)` / `console.log(...)` | Строка в журнал Джарвиса (панель → Логи). |
| `jarvis.version`, `jarvis.api`, `jarvis.arch` | Версия Джарвиса, версия API (1), архитектура. |

Ограничения:

- **Время.** Загрузка скрипта — до 5 секунд, один вызов команды или инструмента — до 20 секунд. Зависший
  скрипт прерывается, пользователь слышит «плагин не справился».
- **Нет** `require`, `import`, `setTimeout`, файлов, процессов и сети в обход `jarvis.fetch`. Нужно больше — пишите нативный плагин.
- Движок — [goja](https://github.com/dop251/goja), это ECMAScript 5.1 и большая часть ES2015+:
  стрелочные функции, `let/const`, классы, шаблонные строки, деструктуризация, `Promise`, async/await.

Ошибку можно выбросить обычным `throw new Error("…")`. Для инструмента текст ошибки уйдёт нейросети, и она
перескажет её человеку. Для команды Джарвис скажет название плагина и текст: `throw new Error("не задан ключ")`
в плагине «Погода» прозвучит как «Погода: не задан ключ». Ошибки в самом коде (опечатка, обращение к
несуществующему) звучат как «плагин не справился», подробности со строкой — в журнале.

<a id="commands"></a>
## Быстрые команды

Быструю команду Джарвис выполняет **без нейросети**: это быстрее, бесплатно и работает, даже когда ключ
кончился. Подходит для фраз, которые говорят всегда одинаково: «подбрось монетку», «какая погода», «курс доллара».

```js
jarvis.command([
  "(какая |что за )?погода( сегодня| завтра)?",
  "нужен ли зонт",
], (text, m) => {
  // text — фраза, m — группы шаблона ("" для несработавших)
  return "Сейчас +5, облачно.";   // строка — Джарвис её скажет
});
```

Как сравнивается фраза:

- Шаблоны — регулярные выражения [RE2](https://github.com/google/re2/wiki/Syntax) (синтаксис Go): без
  обратных ссылок и lookahead. Они **сравниваются со всей фразой**: `^` и `$` добавляются сами.
- Фраза перед сравнением нормализуется: имя «Джарвис» в начале убрано, нижний регистр, `ё` → `е`,
  знаки препинания убраны, пробелы одиночные. «Джарвис, какая погода?» превращается в `какая погода`.
- Обратный слеш в строке JS удваивайте: `"сколько (\\d+) евро"`.

Что вернуть:

| Возврат | Значит |
| :--- | :--- |
| строка | команда выполнена, Джарвис скажет эту строку голосом активного ассистента |
| `""` | выполнена молча, прозвучит короткий сигнал «готово» |
| `null` / `undefined` | не моя фраза: Джарвис проверит команды других плагинов, а потом отдаст фразу нейросети |

Команды плагинов проверяются после «стоп» и до музыки, умного дома и нейросети. Не делайте шаблоны
слишком широкими: `.*погода.*` перехватит «включи песню про погоду».

<a id="tools"></a>
## Инструменты для нейросети

Инструмент — функция, которую нейросеть вызывает сама, когда считает нужным. Описание — это то, по чему
модель решает, звать ли инструмент. Пишите его как инструкцию человеку.

```js
jarvis.tool({
  name: "get_weather",                       // латиница, цифры, _ и -, до 64 символов
  description: "Погода сейчас и прогноз на сегодня, завтра или послезавтра. Город не назвали — не передавай его.",
  parameters: {                              // JSON Schema
    type: "object",
    properties: {
      city: { type: "string", description: "город, если назвали" },
      day:  { type: "string", enum: ["today", "tomorrow", "after_tomorrow"] },
    },
  },
}, (args) => {
  return "Минск: +4, пасмурно.";             // строка (объект уйдёт как JSON), до 8000 символов
});
```

- Имена инструментов ядра заняты: JS-плагин с таким инструментом не запустится, у нативного такой инструмент будет отброшен: `smart_home`, `play_music`,
  `music_control`, `alice_command`, `recall_conversation`, `edit_memory`, `home_assistant`, `xiaomi_home`, `smart_life`.
- Добавляйте к имени префикс плагина (`weather_get`, `gh_issues`), чтобы не столкнуться с другими плагинами.
  Если два плагина дали инструменту одно имя, сработает тот, чей `id` раньше по алфавиту.
- Возвращайте короткий текст по делу: модель перескажет его голосом.

<a id="native"></a>
## Нативные плагины: протокол

Нативный плагин — обычная программа. Джарвис запускает её из папки плагина и общается строками JSON через
stdin/stdout: одна строка — одно сообщение. Всё, что программа пишет в stderr, попадает в журнал Джарвиса.

Окружение при запуске:

| Переменная | Значение |
| :--- | :--- |
| `JARVIS_PLUGIN` | `1` |
| `JARVIS_PLUGIN_ID` | id плагина |
| `JARVIS_PLUGIN_DIR` | папка плагина (рабочая папка процесса) |
| `JARVIS_PLUGIN_DATA` | папка для данных, переживает обновление плагина |
| `JARVIS_PLUGIN_API` | версия API (`1`) |

Сообщение: `{"id": 7, "method": "tool", "params": {...}}`. Ответ на запрос — с тем же `id` и полями `result`
или `error`. Уведомление — без `id` (на него не отвечают).

**Ядро → плагин:**

| Метод | Параметры | Ответ |
| :--- | :--- | :--- |
| `init` | `{api, version, arch, dir, data, settings, info}` | любое значение. Ответить нужно за 15 секунд, иначе плагин считается не запустившимся |
| `tool` | `{name, args}` (`args` — объект аргументов от модели) | строка |
| `command` | `{text, raw}` (`text` нормализован, как у JS) | `{"handled": true, "answer": "…"}`. Отвечать за 3 секунды, иначе фраза уйдёт дальше |
| `settings` | `{settings}` | уведомление |
| `shutdown` | — | уведомление: завершиться. Не успел за 2 секунды — SIGTERM, ещё через 3 — SIGKILL |

**Плагин → ядро:**

| Метод | Параметры | Что делает |
| :--- | :--- | :--- |
| `register` | `{tools: [описания], commands: bool}` | Объявить инструменты и то, что плагин принимает быстрые команды. Отправить после ответа на `init`; можно повторять, если набор поменялся |
| `status` | `{text}` | Строка состояния в панели |
| `log` | `{text}` | Строка в журнал |
| `say` | `{text}` | Сказать голосом активного ассистента |
| `alice` | `{text, silent}` | Запрос Алисе; ответ `true`, если ушёл |

Пример обмена:

```
← {"id":1,"method":"init","params":{"api":1,"version":"0.9.68","arch":"arm64","settings":{},...}}
→ {"id":1,"result":true}
→ {"method":"register","params":{"tools":[{"name":"ping_host","description":"…","parameters":{...}}],"commands":true}}
← {"id":2,"method":"tool","params":{"name":"ping_host","args":{"host":"nas"}}}
→ {"id":2,"result":"nas отвечает, 3 мс"}
```

Жизненный цикл: упавший плагин перезапускается через 2, 5, 15 и 60 секунд. Пять падений за 10 минут — и
плагин остаётся остановленным до перезапуска Джарвиса, а в панели появляется сообщение. Плагин умирает
вместе с Джарвисом (на Linux через `PDEATHSIG`), сиротой не остаётся.

Ресурсы колонки скромные: 220–240 МБ памяти на всё, свободной обычно 60–120 МБ; на `/data` иногда меньше
10 МБ свободно. Держите плагин маленьким: собирайте Go с `-ldflags="-s -w" -trimpath`, не держите лишнего в памяти.

<a id="sdk"></a>
## Нативный плагин на Go: pluginsdk

Пакет [`pluginsdk`](../pluginsdk) прячет протокол:

```go
package main

import (
	"encoding/json"
	"github.com/newfpv/YaJavis/pluginsdk"
)

func main() {
	p := pluginsdk.New()
	var token string
	p.OnInit(func(in pluginsdk.Init) { token, _ = in.Settings["token"].(string) })
	p.OnSettings(func(s map[string]any) { token, _ = s["token"].(string) })
	p.Tool(pluginsdk.ToolDef{
		Name:        "ping_host",
		Description: "Проверить, отвечает ли компьютер в домашней сети.",
		Parameters:  map[string]any{"type": "object", "properties": map[string]any{"host": map[string]any{"type": "string"}}},
	}, func(args json.RawMessage) (string, error) {
		var a struct{ Host string }
		_ = json.Unmarshal(args, &a)
		return a.Host + " отвечает", nil
	})
	p.Command(func(text string) (bool, string) {
		if text == "проверь сервер" {
			return true, "Сервер на месте."
		}
		return false, ""
	})
	p.Run()
}
```

Сборка под обе архитектуры колонок:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=arm64         go build -trimpath -ldflags="-s -w" -o bin/myplugin-arm64 .
CGO_ENABLED=0 GOOS=linux GOARCH=arm GOARM=7   go build -trimpath -ldflags="-s -w" -o bin/myplugin-armv7 .
```

В `plugin.json`: `"kind": "native", "main": "bin/myplugin-{arch}"`. Можно положить обе программы в один
`jarvis-plugin.zip` или сделать два архива: `jarvis-plugin-arm64.zip` и `jarvis-plugin-armv7.zip`.
Тогда колонка скачает только свой.

На другом языке (Rust, C, Zig) — то же самое: читайте строки JSON из stdin, пишите в stdout. Главное —
статическая сборка под `aarch64-linux` и `armv7-linux` (armhf).

<a id="publish"></a>
## Публикация на GitHub, чтобы плагин появился в каталоге

1. Создайте публичный репозиторий. Имя лучше начать с `yajarvis-`: `yajarvis-coin`.
2. Добавьте репозиторию **темы** (About → ⚙ → Topics):
   - `yajarvis-plugin` — обязательно, по ней Джарвис находит плагины;
   - `yajarvis-<категория>` — одна из [категорий](#categories), например `yajarvis-fun`. Без неё плагин попадёт в «Другое».
3. Сделайте **релиз** (Releases → Draft a new release) и приложите архив:
   - `jarvis-plugin.zip` — для JS-плагина или нативного с обеими программами;
   - или `jarvis-plugin-arm64.zip` + `jarvis-plugin-armv7.zip` — нативный, отдельно под каждую архитектуру.

   Джарвис берёт **последний** релиз. Архив — до 24 МБ, в распакованном виде — до 48 МБ.
4. В README репозитория напишите, что умеет плагин, какие фразы понимает, какие настройки и ключи нужны,
   куда ходит в интернет.

Каталог обновляется раз в час (и по кнопке «Обновить каталог»). Поиск GitHub подхватывает новые темы с задержкой до нескольких минут.

Пример workflow, который собирает архив при теге:

```yaml
on: { push: { tags: ['v*'] } }
permissions: { contents: write }
jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: zip -r jarvis-plugin.zip plugin.json main.js
      - run: gh release create "$GITHUB_REF_NAME" jarvis-plugin.zip --title "$GITHUB_REF_NAME"
        env: { GH_TOKEN: '${{ github.token }}' }
```

<a id="versions"></a>
## Версии, обновления и совместимость

- Повышайте `version` в `plugin.json` на каждый релиз. Если в каталоге версия отличается от установленной,
  панель показывает «Обновить до …».
- При обновлении плагина **сохраняются** его настройки, `data.json` и папка `data/`. Остальные файлы заменяются целиком.
- **Обновление самого Джарвиса плагины не трогает**: они лежат отдельно (`/data/opt/jarvisd/plugins`) и
  после обновления запускаются как раньше. API плагинов (`"api": 1`) меняется только с повышением номера;
  старые плагины продолжают работать, пока ядро поддерживает их номер API.
- Нужна возможность из новой версии ядра — укажите `min_core`. На старом ядре такой плагин не встанет,
  а пользователь увидит, до какой версии обновиться.

<a id="official"></a>
## Официальные плагины и обновление ядра

Официальные плагины лежат в этом репозитории: [`plugins/<id>/`](../plugins). Сборка релиза упаковывает
каждый в `plugin-<id>.zip` (`scripts/pack-plugins.go`) и прикладывает к релизу Джарвиса. Список с
категориями и описаниями — [`plugins/index.json`](../plugins/index.json); `recommended: true` отмечает плагины,
которые мастер знакомства предлагает поставить сразу.

Хотите, чтобы ваш плагин стал официальным, — пришлите pull request с папкой в `plugins/` и строкой в
`index.json`. Он должен быть JS-плагином или собираться из исходников в этом репозитории.

Когда функция переезжает из ядра в плагин, обновление не должно её ломать. Для этого у записи в
`index.json` есть правило `auto`:

```json
{"id": "youtube", "category": "media", "auto": {"settings": ["youtube_refresh", "youtube_cookies"]}}
{"id": "something", "category": "system", "auto": {"always": true}}
```

- `always` — плагин нужен всем;
- `settings` — нужен, если в настройках колонки (`settings.json`) задано хотя бы одно из этих полей:
  не пустая строка, не `false`, не `0`, не пустой список.

Перед заменой ядра обновлятель читает `plugins/index.json` **той версии, на которую обновляется**, и ставит
нужные плагины из её же релиза. Если что-то не скачалось, обновление откладывается до следующей попытки,
и колонка остаётся на рабочей версии. После запуска новое ядро ещё раз проверяет то же самое на случай,
если его поставили файлом. Плагины, которые пользователь удалил сам, обратно не ставятся.

<a id="security"></a>
## Безопасность

- JS-плагин видит только объект `jarvis`: сеть через `jarvis.fetch`, своё хранилище, голос и Алису.
  Файлы колонки, другие плагины и ключи Джарвиса ему недоступны.
- Нативный плагин — программа с правами root на колонке. Она может всё. Поэтому неофициальные плагины
  ставятся только после предупреждения, а в карточке видно, откуда плагин и кто автор.
- Архив проверяется при установке: только обычные файлы, без выхода за папку плагина (`../`), без ссылок,
  с ограничением размера. Перед распаковкой проверяется свободное место.
- Не просите у пользователя пароли от аккаунтов. Используйте токены API с минимальными правами
  (поле `password` в настройках) и пишите в README, что и куда отправляет плагин.

<a id="debug"></a>
## Отладка

- **Панель → Логи.** Всё из `jarvis.log`, stderr нативного плагина, ошибки загрузки и вызовов
  (строки начинаются с «плагин <id>:»).
- **Карточка плагина.** Красная строка — почему не запустился (ошибка в скрипте с номером строки,
  нет программы под эту колонку, не тот `api`).
- **Быстро пробовать.** Правите файлы, собираете zip, «Из файла» — плагин с тем же `id` заменяется,
  его данные и настройки остаются.
- На колонке плагины лежат в `/data/opt/jarvisd/plugins/<id>/`, состояние — в `/data/opt/jarvisd/plugins.json`.

<a id="checklist"></a>
## Чек-лист перед публикацией

- [ ] `id` уникальный и не меняется между версиями, `version` повышена.
- [ ] `category` выбрана, такая же тема `yajarvis-<категория>` стоит у репозитория, есть тема `yajarvis-plugin`.
- [ ] Описание в `plugin.json` и README: что умеет, какие фразы, какие ключи нужны, куда ходит в интернет.
- [ ] Шаблоны команд не перехватывают чужие фразы. Проверьте «включи музыку», «выключи свет», «какая погода».
- [ ] Инструменты с префиксом плагина в имени, описания понятны модели.
- [ ] Ошибки понятные: нет ключа, сервис недоступен.
- [ ] Нативный: собран под `arm64` и `armv7`, `CGO_ENABLED=0`, отвечает на `init` быстро, завершается на `shutdown`.
- [ ] В релизе есть `jarvis-plugin.zip` (или `jarvis-plugin-<arch>.zip`) с `plugin.json` внутри.
